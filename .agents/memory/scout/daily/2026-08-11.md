same class of error the closure-record section documents (regex filter dropping
`buttonTestId=` and `testId:` forms). **Never publish a testid-presence claim from a
regex extraction.**

## Brief-writing lesson: propagate the SCOPE decision, not the skill's shape

First draft of `BRIEF.md` told the lead to cut `tests/promote-20260811` and open **two**
draft PRs (PR-UI + PR-Test, cross-linked). Operator caught it: the scope decision was
"UI testids only — defer PR-Test", so the second PR contradicted the decision it was
supposed to implement. Cause: I transcribed the skill's Stage 5 shape, which assumes
both repos promote in the same run, instead of deriving the outputs from the chosen scope.

The thing that made a second branch *feel* necessary was Stage 6's DEV gate. It isn't:
**the gate takes a ref, not a PR.** Verified — `.github/workflows/test-ui-dev.yml` exists
on `origin/automation/base` (and `main`) and its `workflow_dispatch` has a `ref` input
(string, default `main`). So the gate is
`gh workflow run "UI Tests DEV" -f ref=automation/base`. And by the skill's own §3
equivalence logic, `tests/promote-<date>:automation` is byte-identical to
`origin/automation/base:automation` — the branch would be a ref that tests nothing
different. A draft PR over 745 unstabilized commits is also how `#1084` went 10 days
stale, i.e. it would recreate what this run supersedes.

**Generalizable:** when a scope decision narrows a multi-repo skill to one repo, re-derive
every artifact the definition of done names (branches, PRs, cross-links, merge order) from
the narrowed scope. Do not inherit the skill's full-run artifact set and trim by intuition.

## Setup defects found — the documented install path does not work

Three independent breakages, all hit in sequence on a clean venv:

1. **`pip install -e ".[reporting]"` FAILS repo-wide.** `error: Multiple top-level packages
   discovered in a flat-layout: ['reports', 'evidence', 'coverage', 'automation']`. `coverage/`
   (incl. `coverage/area_rollup.py`) and `evidence/` are **tracked** root dirs with valid
   identifier names, so setuptools flat-layout auto-discovery claims them. `pyproject.toml` has
   no `[tool.setuptools] packages` directive to disambiguate. Not machine-local — anyone
   following `CLAUDE.md` hits it. Workaround: install the 14 explicit deps, skip the root
   package (tests import from `automation/` as cwd, so nothing needs the package installed).
2. **`pytest-rerunfailures` is undeclared.** `automation/pytest.ini` addopts carry
   `--reruns=2` + 8 `--only-rerun=` patterns, but the package is in neither `pyproject.toml`
   nor `requirements.txt` ⇒ `pytest: error: unrecognized arguments` — the suite cannot start
   even if (1) were fixed. Present since the initial public-release commit.
3. **Playwright browsers not installed** in a fresh venv — needs
   `.venv/bin/python -m playwright install chromium` (playwright 1.62.0). Expected, but
   undocumented in the install steps.

Fixing (1)+(2) would make `CLAUDE.md`'s documented install actually produce a runnable suite.

## `--only-rerun="TimeoutError"` retries real failures

`pytest.ini` reruns are `--only-rerun`-scoped (looks safe — 502/503/504/connection errors),
but the list also includes **`TimeoutError`**, which is what a genuine Playwright locator
timeout raises. So a real assertion-adjacent failure gets 2 silent retries. Not masking by
itself (a persistent failure still ends red — the smoke failure burned both reruns and stayed
red), but **a retried-then-passed test reads as clean green in the summary line**. Any
promotion/gate evidence must extract per-test rerun counts, not just the pass/fail tally.

## Trap 3 confirmed live: merge `main` ⇒ `npm install` BEFORE anything else

After merging `origin/main` into EliteaUI `automation/testids`, the app **did not boot** —
empty `<div id="root">`, Vite 500s: `Failed to resolve import "@mdx-js/mdx"` and
`Failed to resolve import "exceljs"`. Both are new deps main brought in; `node_modules` lacked
them. `exceljs` is literally the skill's own worked example of this trap.

Diagnostic value: the smoke failure presented as a **locator timeout on a raw handle**
(`locator("main, #root, #app, [role='main']")` → `34 × locator resolved to hidden <div id="root"></div>`)
— i.e. it looked like testid/locator drift and was actually a missing npm dep. **An empty
`#root` means the SPA never mounted; go read the browser console + vite log before triaging a
single test.** One Playwright MCP navigation gave the real cause in seconds.
