
## #110 / ELITEA-1802 — rework: retract a superseded scope exception

Card came back to `Approved` with "Proceed". Not a fresh case — a **rework of a
delivery whose supporting claim canon later overturned by name**.

- 2026-07-16 shipped on "Support Assistant is third-party, its DOM can never carry
  testids". `.agents/testing.md` § Locator policy (connected-first-party-repo
  bullet, #705) says the opposite and cites **#110 by number** as the framing it
  supersedes. The human's own open question in the thread ("do we need to add the
  @eliteaai/elitea-assistant repo?") had been answered by that same seeding work —
  so there was nothing left to park on. Read canon before believing a prior record.
- Analyst found a gap I had NOT flagged: the Step-8 `wait_for_network()` was
  asserting an upload that never fires on attach. **Passing vacuously since July.**
- Delivered: PR #1828, gate 3/3 green (zero reruns), merged `b6c5c578e`.

### Lessons

1. **"Verified promotable" in an old closure record is a claim, not a fact.** #110's
   original record said "fully self-contained, verified promotable". Re-checked with
   a fresh fetch: all 5 testids on `automation/testids`, **none on either `main`**.
   The record was false the moment the connected-repo policy landed. Closure records
   go stale when canon moves — a rework must RE-VERIFY, never inherit.
2. **A vacuous assertion is invisible to every gate.** `wait_for_network()` after an
   action that issues no request settles because nothing is in flight — it cannot
   fail, so it is green forever and no N×-green gate can object. Same selection
   pressure as the substitution problem in § Fidelity policy. The tell: *what
   request/state would make this fail?* If there is no answer, it is decoration.
3. **Run the pristine-HEAD control instead of arguing.** Full-file run showed 2
   reruns on a pre-existing test. The logical case for "not my diff" was strong
   (different class, runs later, import-only module change) — I ran the control
   anyway: byte-identical signature on clean base. 118s converted an argument into
   evidence. Logged as the ledger's first matched control pair.
4. **A clarification card needs the `question` label.** Analyst filed #1827 unlabeled
   (precedent #40 is unlabeled too). Labelled it — `question` is what stops the
   factory from ever working it as a task, and the declared-improvisation protocol
   requires a question card specifically.
5. **Judging the ceiling is the lead's job.** Replacing a case-text observable looks
   like the forbidden "change to what is verified". It was the opposite: the removed
   wait had no failure mode, so nothing verifiable was dropped. Gate on *does this
   strengthen or weaken*, not on *did the text change* — and make the reviewer
   re-test that judgment rather than inherit it (mine did, from the JSX).
