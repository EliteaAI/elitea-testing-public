Traced the actual EliteaUI source (sibling `EliteaUI/` clone, `automation/testids` branch) to check: `agent-version-selector-trigger`/`copy-version-id` (`ApplicationVersionSelect.jsx`) and the actions-menu Publish/Unpublish gates (`usePublishVersion.hooks.js`'s `canShowPublish`, `useUnpublishVersionMenu.hooks.jsx`'s `canUnpublish`) all read the SAME `formik.values.version_details`/`.versions`, fed into Formik via `EditApplication.jsx`'s `enableReinitialize` off `useApplicationDetailsQuery`. Found the actual race: `ApplicationVersionSelect.jsx`'s post-navigate `useEffect` reconciles the URL's `version` param against the (possibly stale) `versions` array and REDIRECTS BACK if the new version isn't in it yet — a race against the publish/unpublish mutations' async `invalidatesTags` refetch (the tag invalidation itself is NOT broken — `applicationDetails` provides the bare/general `TAG_TYPE_APPLICATION_DETAILS` tag which matches regardless of the mutation's `arg.id` being undefined — but the refetch is async and can lose the race against the synchronous effect). Confirmed this is the SAME mechanism whether triggered by the app's own post-publish `navigate()` or a user's manual dropdown reselect (`VersionSelect.jsx` also calls `navigate()` before `onVersionChange`) — explains why the manual workaround is *usually* reliable but not always (~1/10 residual). Posted the full evidence trail to https://github.com/EliteaAI/elitea-testing-public/issues/614#issuecomment-5011102217 — CONFIRMED shared mechanism for the same-page case, explicitly flagged NOT-confirmed for the residual post-`page.reload()` staleness (a reload wipes client state entirely, so that residual case needs a different explanation, plausibly backend-side, unverifiable from the frontend repo). Also corrected a false PR-description checklist line (round 2 claimed "AFS amended" when it hadn't been). Lesson for future rounds: when a commit message asserts two symptoms share a root cause, either point to the actual shared code/state or don't claim it — "responds to the same workaround" is not evidence of "same cause."
