## The problem

`TablePagination`'s `slotProps.select` gets a testid onto the SELECT, but the rows-per-page OPTION
items are generated by MUI itself from `rowsPerPageOptions` — there is no per-item hook, and adding
one would mean replacing the built-in (forbidden: zero-functional-impact rule). A free-floating
`page.locator('[role="listbox"] [role="option"]')` is a policy violation on this project.

## The wiring that works (MUI v7.3, verified 2026-08-28, ELITEA-2322)

```jsx
slotProps={{
  select: {
    'data-testid': 'analytics-tools-pagination-rows-select',
    MenuProps: { slotProps: { list: { 'data-testid': 'analytics-tools-pagination-rows-menu' } } },
  },
  displayedRows: { 'data-testid': 'analytics-tools-pagination-range' },
}}
```

The menu LIST then has a real app testid, and the option items are read as a raw `[role="option"]`
handle SCOPED inside it — #579 exception 1, declared in the page-object method docstring. The menu
is closed again with Escape so the page is left as found.

Note `MenuListProps` is deprecated in MUI v7 — use `slotProps.list`.
