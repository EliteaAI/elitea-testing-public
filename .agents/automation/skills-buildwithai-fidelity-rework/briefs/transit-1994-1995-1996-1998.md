**Scope:** `automation/tests/ui/skills/test_skill_build_with_ai.py`, three
test methods. In every one, `mock_generate_success(...)` exists ONLY to reach
the review step — the case's own observable never depends on what the draft
contains, only on UI mechanics that fire identically regardless of draft
content. This is the cheapest class of fix: drop the mock, call the live
endpoint, keep everything else.

1. `TestSkillBuildWithAIReviewFormCharacterLimits.
   test_review_form_field_character_limit_is_enforced` (ELITEA-1994/1995,
   parameterized via `CHAR_LIMIT_CASES`, ~lines 1756–1842). Uses
   `CHAR_LIMIT_DRAFT_PAYLOAD` with `mock_generate_success` +
   `click_generate_and_wait_for_response(timeout=GENERATE_RESPONSE_TIMEOUT)`.
   **No field-value assertion against the payload exists anywhere in this
   test** — only `response.status == 200` and `approve_button.is_enabled()`
   are checked before the real subject (native-`maxlength` truncation of the
   Description/Instructions field on manual overwrite) takes over. Fix:
   delete the `mock_generate_success` call, swap the timeout to
   `UNMOCKED_GENERATE_RESPONSE_TIMEOUT` (module-level constant already
   defined for ELITEA-1992 — reuse it), nothing else changes.

2. `TestSkillBuildWithAIBackToPromptFromReviewStep.
   test_back_to_prompt_returns_to_input_step_and_preserves_prompt_text`
   (ELITEA-1996, ~lines 1140–1234). Uses `BACK_TO_PROMPT_DRAFT_PAYLOAD` with
   `mock_generate_success`. One payload-value assertion exists (Step 1,
   ~line 1178): `assert modal.get_review_name() == BACK_TO_PROMPT_DRAFT_PAYLOAD
   ["name"]` — this only exists to confirm the review form actually loaded
   the generated draft before "Back to prompt" discards it; the case's real
   Pass criteria (per the file's own comment at ~lines 1108–1111) never
   assert on the draft's specific field values, only on its absence from the
   DOM after Back. Fix: delete the mock, call live
   `expect_generate_response`/`generate_button.click()` (same
   `UNMOCKED_GENERATE_RESPONSE_TIMEOUT`), capture `body =
   response_info.value.json()`, replace the Step-1 comparison with
   `body["name"]`. Every other assertion (Step 3 DOM-removal checks, Step 4
   prompt-text preservation, Step 5 no-leaked-draft-data checks, Step 6
   network/console checks) is untouched — none reference the payload.

3. `TestSkillBuildWithAICancelFromReviewStep.
   test_cancel_from_review_step_does_not_create_skill` (ELITEA-1998,
   ~lines 1415–1483). Uses `CANCEL_FROM_REVIEW_DRAFT_PAYLOAD` with
   `mock_generate_success`. Two payload-value uses: Step 1's pre-check
   (`modal.get_review_name() == CANCEL_FROM_REVIEW_DRAFT_PAYLOAD["name"]`,
   same "confirm it loaded" pattern as #2 above) and Step 4's negative check
   after closing (`assert CANCEL_FROM_REVIEW_DRAFT_PAYLOAD["name"] not in
   names_after`) — proving the cancelled draft's name never reached the
   Skills list. Fix: delete the mock, call live generate (same
   `UNMOCKED_GENERATE_RESPONSE_TIMEOUT`), capture `body =
   response_info.value.json()` (or `response.json()` depending on how the
   live call is invoked — match the pattern used in #2), replace BOTH
   `CANCEL_FROM_REVIEW_DRAFT_PAYLOAD["name"]` reads with the captured
   `body["name"]`. Every other assertion (close-button DOM removal, no
   create-skill call, zero console errors) is untouched.

**Change, per test — mechanical summary:** delete `modal.mock_generate_success
(<payload>)`; where the test calls `click_generate_and_wait_for_response`,
bump its `timeout` argument to `UNMOCKED_GENERATE_RESPONSE_TIMEOUT`; where the
test uses the `with modal.expect_generate_response(...) as response_info:` +
`modal.generate_button.click()` form (ELITEA-1996/1998 do), bump that context
manager's `timeout` the same way; wherever a `*_DRAFT_PAYLOAD["field"]` value
is read for an assertion, replace it with the equivalent field read off the
real response body captured at that call site.
