# Retrospective — 2026-07-30 · memory index compaction

**Scope (operator-set):** memory compaction/optimization only. No efficiency
analysis, no transcript distillation — the `distill-sessions.mjs` pass was
deliberately skipped. Evidence came from the memory corpus itself, the
always-injected `.agents/*` docs, live repo/tracker state, and four read-only
distillation subagents.

**Run by:** scout, interactive. **Acked by the operator before any write.**

---

## The problem

The four `MEMORY.md` indexes had stopped being indexes and become summary
stores. The `memory` skill budgets an index line at **≤120 characters** — "a
hook for deciding whether to open the entry, not a summary of it."

| Role | Lines | Bytes | Median line |
|---|---|---|---|
| qa-engineer | 101 | 65,888 | 610 |
| test-automation-lead | 120 | 50,722 | 419 |
| test-automation-engineer | 70 | 43,191 | 533 |
| scout | 3 | 1,869 | (one line was 1,571) |

Longest single index line: **1,828 chars** (15× budget). All three large
indexes were already being truncated at dispatch, so which entries reached an
agent was decided by file order, not importance.

## Findings

1. **Memory contradicting current canon (worst).** Two indexed lead entries
   instructed the reader to use `git worktree` — one titled *"worktree is now
   mandatory"* — while the 2026-07-24 operator ruling **bans** worktrees and
   says so in three always-injected docs. Memory is the more specific-sounding
   voice, so this actively fought canon.
2. **~19 entries duplicated always-injected text.** Verified mechanically
   against `testing.md` / `workflow.md` / `role-overrides.md` /
   `conventions.md` / `architecture.md` / `profile.md` / `test-automation.yaml`.
   Ironic root cause: scout's own 2026-07-23 `@`-import fix made the shared docs
   arrive uncapped, and memory kept paying for them a second time.
   One check saved a good entry — `eliteaui_testid_commit_message_format`
   (the `[EL-NNNN]` commitlint prefix) is in **no** shared doc, so it stayed.
3. **Five clusters carried one lesson across 5–14 entries.** Lead had 14
   promotability-grep entries, 10 closure-record, 10 shared-tree, 7 sync-guard,
   5 evidence-vs-narration. One file (`label_create_does_not_attach_to_issue.md`)
   was **indexed twice**, at lines 9 and 110.
4. **~250 entries failed the preventive test** ("would this change my FIRST
   move on a task where I wouldn't know to look?"). Per-surface testid maps and
   per-feature quirks only matter once you are already on that surface.
5. **`memory-guard` never ran.** Authored 2026-07-23, marked ACTIVE/nightly.
   `factory/state/` holds `last-{control,intake,reproduce,syncbranch,tal}.log`
   and matching pids — **no** `last-memory-guard.log`, no pid, no crontab entry.
   Its strategy is also wrong for curation: oldest-first, verbatim, merging
   explicitly forbidden. Run today it would archive old durable rules and keep
   recent one-off lookups.
6. **The real budget is far tighter than 32 KB.** Sources disagree — the hook
   reports 32,768; the 2026-07-23 doc+transcript-verified finding is a
   **10,000-char** hard cap on `additionalContext`. Sized to the stricter one.
   Consequence: `project_briefing.md` (5.4–7.6 KB) is now the dominant consumer.

## Two judgement calls the distillers made that the plan got wrong

- **`promotability` was split into two entries, not merged into one.** The 14
  sources answer orthogonal questions — *which* testids belong in the table vs
  *how* to prove one is present. The historical failures came from applying a
  correct grep to an incomplete set and vice versa; merging would have preserved
  exactly that confusion.
- **The engineer's `sanctioned-RED` cluster was refused and split.** Only one of
  the four files was about sanctioned RED. Forcing them together "would produce
  exactly the vague grab-bag the consolidation is meant to kill."

## Known deviations from plan

- **13 of 30 new entries are 4.1–5.2 KB, over the 4 KB entry guideline.**
  Evidence lists were compacted to a count + 3 exemplars (per the skill's
  "seen 15×, not fifteen paragraphs"), with full per-case detail preserved in the
  demoted source files. The residual bulk is rule text; cutting further would cut
  rules. Context: **103 pre-existing entries** were already over 4 KB, one at 16.8 KB.
- **test-automation-lead's payload is 10,441 vs the 10,000 cap** (441 over),
  entirely because its `project_briefing.md` is 7,631 bytes. Under the 32,768 the
  hook reports there is enormous headroom. Judged better to keep real rules than
  cut content to hit a number that cannot be independently confirmed here.

## Deferred — each needs its own ack

1. **No-edit guardrail hook.** Third recurrence in three days, note already
   indexed both times — prose has had its three chances. Narrow design:
   `PreToolUse` on `Edit|Write|MultiEdit`, firing only when agent is
   `test-automation-lead` AND path is outside its memory/audit dirs AND path
   matches app/test source globs AND **the repo is mid-merge** (`.git/MERGE_HEAD`
   or conflict markers). The mid-merge condition pins it to exactly the three
   incidents. Needs an env escape hatch. Recorded in
   `no_edit_guardrail_repo_agnostic.md`. **A guard needs its own ack — never
   folded into a batch of memory diffs.**
2. **`memory-guard` loop.** Retire or rewrite; do not start it as written.
3. **`project_briefing.md` trim.** Now the binding constraint, and ~80% verbatim
   restatement of docs `CLAUDE.md` already imports uncapped. Biggest remaining win.
4. **The 103 pre-existing over-4 KB entry bodies.** Truncated on read today.
