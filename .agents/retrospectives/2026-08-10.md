# Retrospective — 2026-08-10 · context-delivery architecture

**Question asked:** do all three pipeline agents need every `.agents/*` file expanded
via `@`-imports in `CLAUDE.md`, given the per-role hooks — and can the content be
optimized (duplication, per-role scoping) without losing information?

**Method.** 271 sessions distilled (`distill-sessions.mjs --all`, this session
excluded) *plus* direct measurement of the injection pipeline — the question is
architectural, so transcript anecdotes alone would not answer it. Three parallel
read-only agents analyzed each pipeline role's curated memory. Watermark advanced to
271 analyzed sessions.

---

## What every agent actually receives (measured 2026-08-10)

| Channel | Reaches | Size | Capped |
|---|---|---|---|
| `CLAUDE.md` + 8 `@`-imports | every session **and** every sub-agent | 13.7 KB + 96.8 KB ≈ **28k tokens** | no |
| Hook (`SessionStart` / `SubagentStart`) → `RULES.md` + `MEMORY.md` + `project_briefing.md` | per role | lead 22.5 KB · impl 18.2 KB · qa 14.0 KB | nominally 10 KB |
| `AGENT.md` | per role | 12–15.5 KB | no |

**Median opening context on this project: 83.7k tokens** (356 units in the 08-07→09
window each paid it). Comparable projects on this machine open at 16–52k.

Verified by measurement, not assumption:
- `SDLC_SHARED_DOCS=__none__` — **the hook injects no shared docs at all.** They were
  deliberately moved to `@`-imports because the hook's ~10 KB cap truncated them.
- The lead's 22.5 KB injection **is delivered intact** (its transcript record measures
  22,095 B and contains the last line of `project_briefing.md`) — the 10 KB cap is not
  enforced by this host. Over budget, but not currently lossy.

## Findings

### F1 — Per-role delivery is not available without information loss *(measurement)*
The hook is the only per-role channel and its cap is why the current design exists.
`@`-imports inside `.claude/agents/<role>/AGENT.md` would work but those files are
bundle-owned and overwritten by `npx … init --update`. **Decision: keep global
delivery.** (Operator direction was consistent: *"skip B for now"*.)

### F2 — Cross-file duplication was real in mentions, small in bytes *(measurement)*
Six policies were stated in 3–6 files each (`LocatorDescriptor` in all 7 + `CLAUDE.md`;
`env -u GITHUB_TOKEN` in 5; worktrees in 3). After single-sourcing, an 8-word-shingle
overlap detector finds **≤3 shared shingles between any file pair**. But the byte saving
was **~3.1 KB gross / 1.7 KB net**, not the 14–25 KB estimated — most "duplication" was
already one-line pointers plus local context. **The docs are not redundant; they are
large because they carry unique operational detail.** Correcting the estimate is the
finding.

### F3 — 🔴 The real bloat was the per-role memory index, not `CLAUDE.md`
| Role | index lines | entry files | MEMORY.md before → after |
|---|---|---|---|
| test-automation-lead | 51 | 178 | 8,419 → **3,938 B** |
| test-automation-engineer | 59 | 212 | 10,128 → **5,429 B** |
| qa-engineer | 41 | 216 | 6,377 → **3,998 B** |

Whole-store index: **25,457 → 13,898 B (−45%)**. Hook injection: lead 22,482 → **18,001**,
impl 18,220 → **13,521**, qa 13,958 → **11,579**.

### F4 — 🔴 A canon bug in `workflow.md` that memory already knew about, and nobody fixed
The closure-record promotability check shipped
`grep -qE "(data-testid|testid.*=.*$t)"` — **case-sensitive, and requiring `=`**. Proven
by test to drop 2 of 4 real wiring forms:

| Wiring form | old filter | new filter |
|---|---|---|
| `data-testid="x"` | ✅ | ✅ |
| `'data-testid': 'x'` | ✅ | ✅ |
| `buttonTestId="x"` | ❌ **false negative** | ✅ |
| `testId: 'x'` | ❌ **false negative** | ✅ |
| `// TODO: … x testid` (comment) | correctly dropped | correctly dropped |

A false negative writes *"not on main"* into a closure record that is wrong — the
exact #19 failure the fetch rule exists to prevent. **Three memory entries already
documented this** (`closure_grep_must_catch_testid_colon_prop_form.md`,
`provenance_grep_needs_case_insensitive.md`,
`testid_presence_grep_technique.md` — the last one even claims "canon now fixed").
Memory knew; canon did not. This is the escalation ladder's end state: fix the
deterministic source. Done.

### F5 — 🟠 A stale delivery claim that would have caused the exact loss we were avoiding
`role-overrides.md`'s header claimed it was *"hook-injected into every session and
every subagent."* False since `SDLC_SHARED_DOCS=__none__`. Anyone trimming `CLAUDE.md`
on the strength of that sentence would have **silently deleted the entire override
channel**. Corrected with a verified warning block.

### F6 — Three indexed memory entries were contradicted by current code
| Entry | Reality |
|---|---|
| `qa-engineer/pipeline_clear_embedded_chat_is_broken.md` | Fixed for ELITEA-2011; the method is now the correct call. Entry told agents to avoid it. |
| `test-automation-lead/blocker_524_blocks_all_agent_creation.md` | Product bug still OPEN, but `AgentAPI.create_agent()` is fixed (`temperature: None`). Acting on it would park cases that run clean. |
| `test-automation-lead/indexes_tab_removed_by_el5708_…` | Already reworked (`583fa8f1`); also names the wrong ticket (EL-5947, not EL-5708). |
Plus `qa-engineer/open_cross_cutting_defects.md` item #1 (#524), struck for the same reason.

### F7 — 🔵 Largest single optimization available, deliberately NOT applied
The bundle block *"Test Automation Team — shared conventions"* (Team shape + The
pipeline + Working agreements) = **8,326 B, 58% of `CLAUDE.md`** — exists **verbatim in
both `CLAUDE.md` and `AGENTS.md`**. Only the `CLAUDE.md` copy costs tokens (~2.1k/unit).
Not removed: it carries load-bearing rules (no-defect-masking, dispatch-is-the-work,
the standing Workflow opt-in), it is bundle-owned so an update may revert the edit, and
CLAUDE.md trimming was explicitly deferred by the operator. **Proposal on the table:**
keep ~10 invariants as a compact list in `CLAUDE.md` (~1.5 KB), move the prose to
`AGENTS.md` → **−6.8 KB / −1.7k tokens per unit**.

the index is the only thing that costs injection budget.

## Deferred

- **F7 / `CLAUDE.md` trimming** — operator deferred; proposal recorded above.
- **B / dropping `test-automation.yaml` + `team-comms.md` from the import block**
  (−8.8 KB, zero loss for the two IC roles) — operator chose to skip for now.
- **Body-merging the demoted entries** into their survivors. The budget lever is the
  index, and merging bodies risks content loss for zero injection saving. Listed per
  role in the three analysis reports.
- **Hook still over its nominal 10 KB budget** (lead 176%). Not lossy on this host —
  verified — but `lib.sh` warns a host *may* drop an oversized payload to a ~2 KB
  preview, silently. Worth watching, not worth another cut today.
- **An open policy contradiction to settle (needs a human):** `tms_intake_technique.md`
  declares the "≤10 new cards per run" cap and the three-condition already-automated
  exclusion **superseded** (human-confirmed, 2026-07-14; 219→436 filed in one pass),
  while `.agents/test-automation.yaml` § intake and `project_briefing.md` still state
  them as policy. Two indexed sources disagree — scout will not silently pick a winner.
