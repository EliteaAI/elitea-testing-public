### 2. Playwright MCP click gotcha (session `8e0c1151`) — APPLIED

Two qa-engineer Analyst sub-agents (ELITEA-1796, ELITEA-1737) repeatedly hit
`Unexpected token` CSS-parse errors and intercepted clicks on the "Support
Assistant" launcher and other MUI-overlay-guarded buttons when using
`mcp__playwright__browser_click` during live UI exploration. Worked around
with a JS-evaluate click each time, at the cost of several wasted turns (5 of
8 sub-agent tool errors in this session trace back to this one pattern).

**Applied:** added a gotcha entry to
`.agents/memory/qa-engineer/project_briefing.md` telling analysts to use
`browser_evaluate` instead of `browser_click` for overlay-guarded elements.

### 3. Chained sub-locator anti-pattern slipped through 2 review rounds (user-supplied, PR #22 / issue #19) — APPLIED

`automation/pages/skill_form_page.py:272` (merged via PR #22, ELITEA-1737,
commit `fb1dc48`) chains a raw, non-testid CSS selector off an already-correct
`LocatorDescriptor` field, inline in a method body:

```python
content = self.instructions_editor.locator(".cm-content")
```

This is exactly the "locators live only as page-object class fields, never
inside methods" rule already in CLAUDE.md and
`.claude/rules/page-objects.md` — it passed **two** fresh-session reviewer
passes on PR #22 because it disguises itself as compliant (it starts from a
real class field). Confirmed via `git log -S "instructions_editor.locator"`
and cross-checked against the currently-open PR #23 (EL-5634) diff, which
does **not** touch this file and does not cover this specific shape either.

**Applied:**
- `.claude/rules/page-objects.md` — added this exact case as a named
  anti-pattern with the real code, plus a sign-off checklist line.
- `.agents/memory/qa-engineer/project_briefing.md` — reviewer checklist bullet
  sharpened to explicitly name "raw selector chained off an existing field
  inside a method" and instructs grepping diffs for `\.locator(` inside
  method bodies.
- GitHub issue #19 (`[Automate][ELITEA-1737] Import Skill (Base Version)`)
  reopened with a comment describing the root cause and the fix needed in
  `skill_form_page.py`. Left unassigned pending user approval — the actual
  code fix was explicitly deferred, not done as part of this retro.
